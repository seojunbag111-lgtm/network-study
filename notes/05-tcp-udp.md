## 2. 重要な概念 (Key Concepts)

### 1. ポート

- ポートは、ホスト内でネットワーク通信の相手となるサービスやプロセスを区別するために使用される。
- ポート番号は、ポートを識別するための番号である。
- ポート番号は、ソケットを通じて行われる通信で使用される。
- ソケットに設定されたポート番号を確認することで、そのポートを使用しているサービスやプロセスを確認できる。

### 2. TCP

- TCPは、コネクション指向型の通信プロトコルである。
- TCPは、データが順番通りに受信されることを保証する。
- データの順番が入れ替わったり、データの損失が発生した場合には、必要に応じて再送を行う。
- TCPは、受信側が受信可能なデータ量を考慮して送信を行う。

### 3. UDP

- UDPは、非コネクション型の通信プロトコルであり、データの順番や損失に対する再送などの制御を基本的に行わない。
- UDPは、宛先がデータを受信できる状態であるかを確認せずにデータを送信する。
- UDPは、リアルタイム性が重視されるマルチメディア通信などに適している。

### 4. TCPヘッダ

| フィールド | 役割 |
|---|---|
| Source Port | 送信元のポート番号を表す。 |
| Destination Port | 宛先のポート番号を表す。 |
| Sequence Number | セグメントに含まれるデータの先頭バイトの番号を表す。 |
| Acknowledgement Number | 次に受信することを期待するバイトのSequence Numberを表す。 |
| Flags | TCP通信を制御するための情報を表す。 |
| Window Size | 受信側が追加で受信可能なデータ量を表す。 |

- Sequence Numberは、送信したデータのバイト数に応じて増加する。

### 5. TCPフラグ

- TCPフラグは、TCP通信を制御するために使用される。
- SYNは、TCP接続を開始する際に使用される。
- FINは、TCP接続を正常に終了する際に使用される。
- RSTは、TCP接続を強制的にリセットする際に使用される。
- PSHは、受信したデータをバッファに保持し続けず、アプリケーション側へ速やかに渡すことを要求するために使用される。

### 6. TCP接続の確立と終了

#### 3-way handshake

TCP接続を確立する際には、3-way handshakeが行われる。

1. クライアントがサーバーにSYNを送信し、接続を要求する。
2. サーバーはSYNとACKを送信し、接続要求を受け取ったことを通知する。
3. クライアントがACKを送信し、TCP接続が確立される。

- TCP接続を確立する際には、SYNセグメントのTCP Optionを通じてMSSを通知することがある。

#### 4-way handshake

TCP接続を終了する際には、4-way handshakeが行われる。

1. 一方のホストがFINを送信し、接続の終了を要求する。
2. 相手側はACKを送信し、FINを受信したことを通知する。
3. 相手側もFINを送信し、自分側の通信終了を要求する。
4. 最初にFINを送信した側がACKを送信し、接続が終了する。
