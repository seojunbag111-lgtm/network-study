## 2. Linuxのネットワークコマンド

### 1. ip link / ip addr

#### ip link

- `ip link`は、Linuxのネットワークインターフェースの情報を確認するためのコマンドである。
- 主にインターフェース名、インターフェースの状態、MACアドレス、MTUなどを確認できる。
- UPは、そのネットワークインターフェースが有効になっていることを表す。
- MTUは、ネットワークインターフェースで一度に送信できるIPパケットの最大サイズを表す。

#### ip addr

- `ip addr`は、ネットワークインターフェースに割り当てられたIPアドレスを確認するためのコマンドである。
- inetではIPv4アドレス、inet6ではIPv6アドレスを確認できる。
- IPアドレスと一緒にプレフィックス長も確認できる。

#### ip linkとip addrの違い

- `ip link`では、ネットワークインターフェースの状態やMACアドレス、MTUなどの情報を確認できる。
- `ip addr`では、ネットワークインターフェースの情報に加えて、そのインターフェースに割り当てられたIPアドレスも確認できる。

### 2. ip route

- `ip route`は、Linuxのルーティングテーブルを確認するためのコマンドである。
- ルーティングテーブルには、宛先ネットワーク、ネクストホップ、使用するネットワークインターフェースなどの経路情報が登録されている。
- defaultはデフォルトルートを表し、より具体的に一致する経路がない場合に使用される。
- viaは、パケットを次に転送するネクストホップを表す。
- devは、パケットの送信に使用するネットワークインターフェースを表す。
- 例えば、以下のような経路が表示される。

```text
default via 172.21.48.1 dev eth0
172.21.48.0/20 dev eth0
```

- default via 172.21.48.1 dev eth0は、他に一致する経路がない場合、eth0を使用してネクストホップである172.21.48.1へパケットを転送することを表す。
- 172.21.48.0/20 dev eth0は、172.21.48.0/20宛てのパケットをeth0から直接送信することを表す。

### 3. ip neigh

- `ip neigh`は、LinuxのNeighbor Tableを確認するためのコマンドである。
- Neighbor Tableには、同じネットワーク上に存在するホストのIPアドレスとMACアドレスの対応情報が保存されている。
- IPv4では、ARPによって取得したIPアドレスとMACアドレスの対応情報を確認できる。
- 例えば、以下のような情報が表示される。

```text
172.21.48.1 dev eth0 lladdr 00:15:5d:7d:e7:6b DELAY
```

- 172.21.48.1は、NeighborのIPアドレスを表す。
- dev eth0は、そのNeighborとの通信に使用するネットワークインターフェースを表す。
- lladdrは、NeighborのMACアドレスを表す。
- DELAYなどの表示は、Neighborの状態を表す。

### 4. ss

- `ss`は、Linuxでソケットの情報を確認するためのコマンドである。
- TCPやUDPのソケット、使用されているIPアドレスやポート番号、通信状態などを確認できる。
- `ss -t`を使用するとTCPソケット、`ss -u`を使用するとUDPソケットを確認できる。
- `ss -l`を使用すると、接続を待ち受けているソケットを確認できる。
- `ss -n`を使用すると、IPアドレスやポート番号をホスト名やサービス名に変換せず、数値のまま表示する。
- `ss -tuln`のように複数のオプションを組み合わせることもできる。 このコマンドでは、待ち受けているTCP・UDPソケットと、そのIPアドレスやポート番号を確認できる。

### 5. ping

- pingは、宛先ホストとの通信が可能かどうかを確認するために使用されるコマンドである。
- ICMP Echo Requestを宛先へ送信し、ICMP Echo Replyが返ってくることで通信を確認する。
- 応答結果からRTT(Round Trip Time)を確認することもできる。
- 例えば、`ping 8.8.8.8`のように使用する。
- 8.8.8.8にICMP Echo Requestを送信し、応答の有無やRTTなどを確認できる。

### 6. traceroute

- tracerouteは、宛先までの通信経路を確認するために使用されるコマンドである。
- パケットのTTLを利用して、宛先までに経由するルータを順番に確認する。
- TTLはルータを経由するたびに減少し、0になるとパケットが破棄される。この仕組みを利用して、経路上のルータを確認する。
- 例えば、`traceroute 8.8.8.8`のように使用する。
- 8.8.8.8までの通信で経由するルータを確認できる。

### 7. dig / nslookup

- digとnslookupは、DNSによる名前解決の結果を確認するために使用されるコマンドである。
- ドメイン名から取得したIPアドレスや、名前解決に使用されたDNSサーバーなどの情報を確認できる。
- digは、DNSに関するより詳細な情報を確認する場合に使用する。
- 例えば、`dig google.com`、`nslookup google.com`のように使用する。
- google.comの名前解決を行い、取得したIPアドレスなどを確認できる。

### 8. curl

- curlは、URLを指定してサーバーとデータを送受信するために使用されるコマンドである。
- HTTP通信では、WebサーバーへHTTPリクエストを送信し、返されたHTTPレスポンスを確認できる。
- 例えば、`curl https://example.com`のように使用する。
- `curl -I https://example.com`のように-Iオプションを使用すると、レスポンスヘッダを確認できる。

### 9. tcpdump

- tcpdumpは、Linuxでネットワークを流れるパケットをキャプチャして確認するためのコマンドである。
- ネットワークインターフェースを指定したり、条件を設定したりすることで、確認するパケットを絞り込むことができる。
- `sudo tcpdump -i eth0`は、eth0を通過するパケットをキャプチャして確認できる。
- `sudo tcpdump -i eth0 icmp`のようにeth0を通過するICMPパケットだけを確認できる。

## 3. 学びと考察 (Reflection)

- Linuxでは、ネットワークの状態や設定を確認するために、目的に応じてさまざまなコマンドを使用することを学んだ。
- これまで学習したIPアドレス、ルーティング、ARP、ソケット、DNS、HTTPなどの仕組みを、Linuxのコマンドを通して実際に確認できることを理解した。
- ネットワークに問題が発生した場合、一つのコマンドだけではなく、確認したい情報に応じて複数のコマンドを使い分けることが重要だと考えた。
