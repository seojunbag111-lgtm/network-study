## 2. 重要な概念 (Key Concepts)

### 1. IPv4

- IPv4アドレスは32ビットで構成され、8ビットずつ4つに分けて表記する。
- IPv4アドレスは、ネットワークIDとホストIDで構成される。
- サブネットマスクによって、ネットワークIDとホストIDの境界を区別する。
- ホストIDがすべて0の場合はネットワーク自体を表し、すべて1の場合はブロードキャストに使用される。例えば、ホストIDが8ビットの場合、ホストには1～254の範囲を割り当てることができる。
- 現在では、IPアドレスの浪費が発生しやすいクラス単位の方式ではなく、ネットワークIDとホストIDの境界を柔軟に指定できるCIDR方式が主に使用される。
- CIDRでは、IPアドレスの後ろに`/24`のような形式で、ネットワークIDとして使用するビット数を表す。
- パブリックIPアドレスは、ISPなどから割り当てられ、ネットワーク上で一意に使用されるIPアドレスである。
- プライベートIPアドレスは、内部ネットワークで使用されるIPアドレスである。
- ループバックアドレスは、ホスト自身を指すために使用される。
- マルチキャストは、簡単に言えばユニキャストとブロードキャストの中間に位置し、特定のグループに属する複数の宛先にデータを送信する方式である。

### 2. セグメントとパケット

- セグメントは、ストリームをMSSを上限として分割したTCPレベルのデータ単位である。
- セグメントはTCPヘッダとデータで構成され、パケットはIPヘッダとセグメントで構成される。
- パケットのIPヘッダには、送信元と宛先のIPアドレスなどの情報が含まれる。
- 各レイヤーでヘッダなどの情報を付加してデータを再構成する過程をカプセル化と呼び、その逆の過程をデカプセル化と呼ぶ。
- レイヤー2では、パケットにイーサネットヘッダとトレーラを付加してフレームを生成する。
- データがルータを経由して転送される際には、次の転送先に応じてフレームが再構成され、送信元と宛先のMACアドレスも変化する。
- 宛先のNICがフレームを受信すると、デカプセル化によってデータが取り出され、最終的にプロセスがデータを受け取る。
- 一般的なイーサネットでは、MTUとして1500バイトが使用される。
- MTUが1500バイトで、IPヘッダとTCPヘッダがそれぞれ20バイトの場合、MSSは1460バイトとなる。

### 3. IPv4ヘッダのフィールド

| フィールド | 役割 |
|---|---|
| Version | IPのバージョンを表す。IPv4では4となる。  |
| IHL | IPv4ヘッダの長さを表す。  |
| Total Length | ヘッダを含むパケット全体の長さを表す。  |
| Identification | フラグメント化されたパケットを識別するために使用される。 |
| DF / MF | フラグメント化に関する情報を表す。  |
| Fragment Offset | 分割されたデータの位置を表す 。|
| TTL | パケットが通過できるルータの回数を制限する。 |
| Protocol | 上位レイヤーのプロトコルを識別するために使用される。 |
| Header Checksum | IPv4ヘッダのエラーを検出するために使用される。 |
| Source Address | 送信元のIPv4アドレスを表す。 |
| Destination Address | 宛先のIPv4アドレスを表す。  |

- TTLはルータを通過するたびに減少し、0になるとパケットは破棄される。
- TTLは、パケットがネットワーク上を無限に転送され続けることを防ぐ役割を持つ。
- TTLの初期値はOSによって異なり、一般的にWindowsでは128、Linuxでは64が使用される。

### 4. トラフィック分析

- ネットワーク障害の調査や分析には、Wiresharkなどのプロトコルアナライザを使用できる。
- AWSでは、ENIの設定を通じてVPC Traffic Mirroringを利用できる。

### 5. ループバックアドレス

- ループバックアドレスは、ホストが自分自身と通信するために使用するIPアドレスである。
- IPv4では127.0.0.0/8がループバック用に予約されており、代表的に127.0.0.1が使用される。
- トラフィックはNICまで到達しないため、物理的なネットワークには送信されない。
- 同じホスト内のプロセス間でループバック通信を行う場合、データはホスト内部で宛先のプロセスへ渡される。
