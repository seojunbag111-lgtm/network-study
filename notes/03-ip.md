## 2. 重要な概念 (Key Concepts)

### 1. IPv4

- IPv4アドレスは、32ビットで構成され、8ビットずつ4つに分けて表記する。
- IPv4アドレスは、ネットワークIDとホストIDで構成される。
- サブネットマスクによって、ネットワークIDとホストIDの境界を区別する。
- ホストIDがすべて0の場合は、ネットワーク自体を表し、すべて1の場合は、ブロードキャストに使用される。例えば、ホストIDが8ビットの場合、ホストには1～254の範囲を割り当てることができる。
- 現在では、IPアドレスの浪費が発生しやすいクラス単位の方式ではなく、ネットワークIDとホストIDの境界を柔軟に指定できるCIDR方式が主に使用される。
- CIDRでは、IPアドレスの後ろに`/24`のような形式で、ネットワークIDとして使用するビット数を表す。
- パブリックIPアドレスは、ISPなどから割り当てられ、ネットワーク上で一意に使用されるIPアドレスである。
- プライベートIPアドレスは、内部ネットワークで使用されるIPアドレスである。
- ループバックアドレスは、ホスト自身を指すために使用される。
- マルチキャストは、簡単に言えば、ユニキャストとブロードキャストの中間に位置し、特定のグループに属する複数の宛先にデータを送信する方式である。

### 2. セグメントとパケット

- セグメントは、ストリームをMSSを上限として分割したTCPレベルのデータ単位である。
- セグメントは、TCPヘッダとデータで構成され、パケットは、IPヘッダとセグメントで構成される。
- パケットのIPヘッダには、送信元と宛先のIPアドレスなどの情報が含まれる。
- 各レイヤーでヘッダなどの情報を付加してデータを再構成する過程をカプセル化と呼び、その逆の過程をデカプセル化と呼ぶ。
- 一般的なイーサネットでは、MTUとして1500バイトが使用される。
- MTUが1500バイトで、IPヘッダとTCPヘッダがそれぞれ20バイトの場合、MSSは1460バイトとなる。

### 3. IPv4ヘッダのフィールド

| フィールド | 役割 |
|---|---|
| Version | IPのバージョンを表す。IPv4では4となる。 |
| IHL | IPv4ヘッダの長さを表す。 |
| Total Length | ヘッダを含むパケット全体の長さを表す。 |
| Identification | フラグメント化されたパケットを識別するために使用される。 |
| DF / MF | フラグメント化に関する情報を表す。 |
| Fragment Offset | 分割されたデータの位置を表す。 |
| TTL | パケットが通過できるルータの回数を制限する。 |
| Protocol | 上位レイヤーのプロトコルを識別するために使用される。 |
| Header Checksum | IPv4ヘッダのエラーを検出するために使用される。 |
| Source Address | 送信元のIPv4アドレスを表す。 |
| Destination Address | 宛先のIPv4アドレスを表す。 |

- TTLは、ルータを通過するたびに減少し、0になるとパケットは破棄される。
- TTLは、パケットがネットワーク上を無限に転送され続けることを防ぐ役割を持つ。
- TTLの初期値は、OSによって異なり、一般的にWindowsでは128、Linuxでは64が使用される。

### 4. トラフィック分析

- ネットワーク障害の調査や分析には、Wiresharkなどのプロトコルアナライザを使用できる。
- AWSでは、ENIの設定を通じてVPC Traffic Mirroringを利用できる。

### 5. ループバックアドレス

- ループバックアドレスは、ホストが自分自身と通信するために使用するIPアドレスである。
- IPv4では、127.0.0.0/8がループバック用に予約されており、代表的に127.0.0.1が使用される。
- トラフィックは、NICまで到達しないため、物理的なネットワークには送信されない。
- 同じホスト内のプロセス間でループバック通信を行う場合、データは、ホスト内部で宛先のプロセスへ渡される。

### 6. パケットのフラグメンテーション

- フラグメンテーションは、パケットのサイズが転送先のネットワークのMTUを超える場合に発生することがある。
- VPNなどの利用によって、利用可能なMTUが小さくなる場合がある。
- フラグメンテーションされたパケットは、宛先のホストで再構築される。
- フラグメンテーションが多く発生すると、通信効率の低下や負荷の増加につながる可能性がある。

### 7. DHCP

- DHCPは、ネットワーク接続に必要な設定を自動的に行うためのプロトコルである。
- DHCPでは、サーバーがクライアントに使用するIPアドレスを割り当てる。
- ルータには、一般的にDHCPの機能が搭載されている。
- 企業などの大規模な環境では、DHCPサーバーを設置し、家庭のような小規模な環境では、一般的に無線LANルータがDHCPの役割を果たす。

### 8. ARP

- ARPは、IPアドレスからMACアドレスを確認するために使用されるプロトコルである。
- デフォルトゲートウェイのMACアドレスが必要な場合、ARP Requestを送信してMACアドレスを確認する。
- ARP Requestは、ブロードキャストで送信され、宛先MACアドレスには`FF-FF-FF-FF-FF-FF`が使用される。
- ARP Replyによって、MACアドレスを確認し、その情報をARPテーブルに保存する。
- ARPには、応答の正当性を確認する仕組みがないため、ARP Spoofing攻撃に悪用される可能性がある。

### 9. RTT

- RTTは、データを送信してから応答が返ってくるまでの往復時間である。
- Pingを使用して、特定のホストとのRTTを測定できる。
- Pingでは、ICMPプロトコルが使用される。
- 異なるISPを経由する通信では、同じISP内の通信と比べて経路が長くなり、RTTが高くなる場合がある。

## 3. 通信の流れ・仕組み (How It Works)

1. 送信側では、TCPヘッダとデータからセグメントが構成される。
2. セグメントにIPヘッダを付加してパケットを生成する。
3. レイヤー2では、パケットにイーサネットヘッダとトレーラを付加してフレームを生成する。
4. データがルータを経由して転送される際には、次の転送先に応じてフレームが再構成され、送信元と宛先のMACアドレスも変化する。
5. 宛先のNICがフレームを受信すると、デカプセル化によってデータが取り出され、最終的にプロセスがデータを受け取る。

## 4. 学びと考察 (Learning & Insights)

- セグメント、パケット、フレームの関係を学ぶことで、各レイヤーでデータに必要な情報が付加されながら通信が行われる仕組みを理解した。
- IPアドレスだけでなく、MACアドレスやルータなど複数の要素を通じてデータが宛先まで転送されることを理解した。
