## 2. 重要な概念 (Key Concepts)

### 1. URIとURL

- URIは、インターネット上のあるリソースを識別するための表現である。
- URLは、そのリソースの場所とアクセスする方法を表す。
- URLは、URIに含まれる概念である。
- Webアドレスと呼ばれる`https://www.google.com`などは、URLであると同時にURIである。

### 2. HTTP通信

- HTTP通信は、クライアントがサーバーにHTTPリクエストを送信し、サーバーがHTTPレスポンスをクライアントに返す仕組みである。
- HTTPリクエストには、Method、URI、Header、Bodyなどの情報が含まれる。
- HTTPレスポンスには、Status Code、Header、Bodyなどの情報が含まれる。
- Webアプリケーションでは、CRUD(Create、Read、Update、Delete)の処理をHTTP Methodと対応付けて設計することがある。

#### HTTP Method

- HTTP Methodは、HTTPリクエストの目的や動作を表すものである。

| Method | 役割 |
|---|---|
| GET | リソースを参照する。 |
| POST | リソースを生成する。 |
| PUT | リソース全体を修正する。 |
| PATCH | リソースの一部を修正する。 |
| DELETE | リソースを削除する。 |

#### Status Code

- Status Codeは、HTTPレスポンスでリクエストの処理結果を表す三桁の数字である。

| Status Code | 意味 |
|---|---|
| 200 OK | リクエストが正常に処理された。 |
| 201 Created | リソースの生成に成功した。 |
| 400 Bad Request | リクエストが不正である。 |
| 404 Not Found | リソースが存在しない。 |
| 500 Internal Server Error | サーバー内部でエラーが発生した。 |

### 3. Web Serviceの構造

- 初期のWebでは、WebブラウザはWebサーバーからHTMLなどのリソースを取得し、それを解析・レンダリングして表示していた。
- Webサービスが発展すると、ログインや検索などの処理が必要になり、サーバー側でアプリケーションロジックを実行するようになった。
- クライアントは、必ずしもWebサーバーを経由するとは限らず、REST APIを通じてAPIサーバーに直接アクセスすることもできる。
- Webサーバーは、HTTPリクエストの受付や静的リソースの配信などを行い、WASはアプリケーションの処理を実行する。
- データベースは、サービスで使用するデータを保存する。

### 4. Cookieとセッション

- HTTPは、基本的に各リクエストを独立して処理する。
- ログイン状態など、複数のリクエスト間で状態を維持する必要がある場合、Cookieやセッションなどが利用される。
- セッション IDをCookieとしてブラウザに保存し、以降のHTTPリクエストに含めて送信することで、サーバーはユーザーのセッションを識別できる。

### 5. Modern Web

- Modern Webでは、サーバーがREST APIなどを通じてJSON形式のデータを返し、クライアント側でHTMLを生成する構成も広く使われている。
- Modern Web環境の認証やログイン状態の管理には、トークンを利用する方式やCookieを利用する方式などがある。

### 6. JWT

- JWTは、ユーザーに関する情報などをトークンとして表現するための形式であり、トークンベースの認証で利用されることがある。
- クライアントは、トークンを保存し、REST APIを呼び出す際にサーバーに再送し、サーバーはSignatureや有効期限などを確認してトークンの有効性を検証する。
- トークンは、Header、Payload、Signatureで構成されており、サーバーはSecret Keyなどを使用してSignatureを生成・検証することで、トークンが改ざんされていないか確認できる。
- JWTを利用することで、サーバー側にセッション情報を保持しない構成を実現することもできるため、複数のサーバーで構成される環境でも利用しやすい。
- 発行済みのトークンを有効期限前に無効化する必要がある場合は、ブラックリストなどの仕組みを利用することがある。また、リフレッシュトークンを利用して新しいアクセストークンを発行する方式もある。
- Redisサーバーを設定してログアウトしたユーザーのトークンをブラックリストに登録し、有効期限が切れる前に無効化できる。

### 7. SOPとCORS

- SOPは、異なるOriginのリソースへのアクセスを制限するブラウザレベルのセキュリティポリシーである。
- Originは、プロトコル、ホスト、ポートの組み合わせによって判断される。
- SOPによって、異なるOriginから取得したレスポンスをJavaScriptから自由に読み取ることが制限される。
- CSRFは、ユーザーがログイン済みのWebサービスに対して、攻撃者がユーザーの意図しないリクエストを送信させる攻撃である。
- SOPだけでは、CSRFを完全に防ぐことはできない。
- CORSは、異なるOriginからのアクセスを許可する場合に、サーバー側から許可するOriginなどを指定するための仕組みである。
- サーバーからレスポンスが返されても、CORSの条件を満たしていない場合、ブラウザはJavaScriptからそのレスポンスを利用できないように制限する。

### 8. MSA

- MSAは、システムを役割ごとの複数のマイクロサービスに分割し、それぞれが処理を担当するアーキテクチャである。
- API Gatewayは、クライアントからのリクエストを複数のマイクロサービスの前で受け付け、適切なサービスへ引き渡す単一のエントリーポイントとして機能する。

## 3. 通信の流れ・仕組み (How It Works)

### Web Serviceの基本的な構造

```text
クライアント
  ↓
Webサーバー
  ↓
WAS
  ↓
データベース
```

- クライアントからのHTTPリクエストをWebサーバーが受け付け、必要に応じてWASに処理を渡す。
- WASはアプリケーションの処理を行い、必要に応じてデータベースのデータを利用する。

### Modern Webの通信

```text
クライアント
  ↓ HTTPリクエスト
APIサーバー
  ↓ JSON
クライアント
  ↓
レンダリング
```

- クライアントがREST APIを通じてAPIサーバーにHTTPリクエストを送信する。
- APIサーバーはJSON形式のデータを返し、クライアント側でそのデータを利用して画面を生成する。

## 4. 学びと考察 (Learning & Insights)

- Webサービスでは、Webサーバー、WAS、APIサーバー、データベースなどが役割を分担して処理を行っていることを理解した。
- Cookieやセッション、JWT、SOP、CORSなどを学ぶことで、Webサービスでは通信だけでなく、認証やセキュリティのための仕組みも必要であることを理解した。
