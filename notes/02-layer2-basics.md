# 02-layer2-basics

## 1. 学んだこと (Learning)

- NIC
- MACアドレス
- フレーム
- L2スイッチ
- ブロードキャスト

## 2. 重要な概念 (Key Concepts)

### 1. NIC

- NICはNetwork Interface Cardの略であり、LANカードなどが該当する。
- NICにはMACアドレスが割り当てられている。
- 有線にはイーサネット、無線にはIEEE 802.11系の規格などがある。

### 2. MACアドレス

- MACアドレスはハードウェアアドレスとも呼ばれ、ネットワークインターフェースを識別するために使用される。
- MACアドレスはハードウェアに割り当てられているが、ソフトウェア上で変更して使用することもできる。
- `ip link`を使って、ネットワークインターフェースのMACアドレスを確認できる。

### 3. フレーム

- フレームは、レイヤー2で扱われるデータの単位である。
- イーサネットでは、MACアドレスなどの情報を含むフレームという単位でデータを扱う。

#### イーサネットフレームのフィールド

| フィールド | 役割 |
|---|---|
| Destination MAC Address | 宛先のMACアドレスを表す。 |
| Source MAC Address | 送信元のMACアドレスを表す。 |
| Type | Dataに含まれる上位レイヤーのプロトコルの種類を表す。 |
| Data | 上位レイヤーのデータが含まれる。 |
| Trailer | 転送中のエラーを検出するための情報が含まれる。 |

### 4. L2スイッチ

- L2スイッチは、宛先のMACアドレスを基準に、データをどのインターフェースへ転送するかを決定する。
- L2スイッチは、MACアドレスに関する情報をテーブルで管理する。

#### アクセススイッチ

- アクセススイッチは、エンドポイントに直接接続されるスイッチである。
- スイッチングハブは、アクセススイッチの一例として挙げられる。

#### ディストリビューションスイッチ

- 複数のアクセススイッチと接続し、異なるアクセススイッチに接続されたエンドポイント間の通信を支援する。
- 一般的に、LANの単位を論理的に再構成するVLAN機能を提供する。

### 5. AWS環境におけるL2

- AWS環境では、L2レベルのネットワークはユーザーに直接公開されておらず、ユーザーが設定することもできない。
- L2の仕組みは抽象化され、AWSによって自動的に処理される。
- ユーザーは主にL3を基準としてネットワークを構成する。
- MACアドレスは存在するが、ユーザーがMACアドレスを基準として通信を構成することは基本的にない。

### 6. ブロードキャスト

- 宛先がブロードキャストアドレスであるデータは、ブロードキャストが到達する範囲内の他のホストに送信される。
- ブロードキャストは必要な場合もあるが、過剰に発生するとネットワークの効率を低下させる原因となる。
- ブロードキャストMACアドレスは`FF-FF-FF-FF-FF-FF`であり、48ビットすべてが1で構成されている。
- ブロードキャストでは、レイヤー2では宛先MACアドレスにブロードキャストMACアドレスを使用し、レイヤー3では宛先IPアドレスにブロードキャストアドレスを使用する。
- LANとWANの境界を考える際には、ブロードキャストが到達する範囲やルータの位置を参考にすることができる。

## 3. 通信の流れ・仕組み (How It Works)

1. 送信側は、宛先MACアドレスなどの情報を含むフレームを送信する。
2. L2スイッチは、フレームの宛先MACアドレスを確認する。
3. L2スイッチは、管理しているMACアドレスの情報を基に、転送先のインターフェースを決定する。
4. フレームは、決定されたインターフェースから宛先側へ転送される。

## 4. 学びと考察 (Learning & Insights)

- MACアドレス、フレーム、L2スイッチの関係を学び、レイヤー2ではMACアドレスを基準としてデータが転送される仕組みを理解した。
- 一般的なネットワークではL2の仕組みが重要である一方、AWS環境ではL2が抽象化されており、ユーザーは主にL3を基準としてネットワークを構成するという違いを理解した。
