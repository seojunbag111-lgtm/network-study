# 03-routing-and-path

## 1. 目的 (Objective)

この実習では、`ip route`を使用してルーティング情報を確認し、`traceroute`を使用して実際の通信経路を確認する。

## 2. 環境 (Environment)

- OS : Linux (Ubuntu)
- Environment : WSL2
- Tools / Commands : `ip route`、`traceroute`

## 3. 実習 (Practice)

### Step 1. ルーティング情報の確認

```bash
ip route
```

```text
default via 172.21.48.1 dev eth0 proto kernel
172.21.48.0/20 dev eth0 proto kernel scope link src 172.21.60.158
```

traceroute 8.8.8.8

## 4. 結果 (Result)

`ip route`と`traceroute 8.8.8.8`の実行結果から、以下の情報を確認した。

- `ip route`でデフォルトルートが設定されていることを確認した。
- デフォルトルートのネクストホップが172.21.48.1、インターフェースがeth0であることを確認した。
- `traceroute`では、8.8.8.8まで11ホップで到達した。
- `traceroute`の1ホップ目が172.21.48.1であることを確認した。

## 5. 結果の分析 (Analysis)

`ip route`のデフォルトルートに設定されているネクストホップである172.21.48.1と`traceroute`の1ホップ目が一致した。 この結果から、外部のネットワーク宛てのパケットがルーティングテーブルに基づいてネクストホップに送信されていることを実際に確認できた。

## 6. 学びと考察 (Learning & Insights)

- `ip route`と`traceroute`を使用することで、ルーティングテーブルに登録されている経路情報と、実際の通信経路の関連性を確認することができた。
- ルーティングテーブルのデフォルトルートと実際の通信経路を比較することで、外部ネットワーク宛てのパケットがネクストホップを経由して転送される仕組みを理解した。
